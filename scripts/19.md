# 19/24 — 도메인·키·엔티티 무결성 제약조건

## 원본 근거
Library 「2장. 관계 데이터 모델과 제약조건 (1)(1).pdf」 39~40쪽 직접 확인.
- 39쪽: 도메인 제약조건 — 원자값, 자료형(정수형·문자형 등), 디폴트 값·CHECK를 통한 허용 범위 제한.
- 39쪽: 키 제약조건 — 키 애트리뷰트의 중복값 금지.
- 40쪽: 엔티티 무결성 — 기본 키를 구성하는 모든 애트리뷰트의 NULL 금지.
- 40쪽: 엔티티 무결성은 대체 키에 적용되지 않음. 데이터 정의문에서 기본 키 구성요소 명시.
- 원본에 실제 데이터 표가 없으므로 임의 학생/직원 표·번호·이메일을 추가하지 말 것.

## 6컷 상세 대본
1. **도입(상단 와이드)**: 두 여성만 등장. 마법 도서관의 봉인 장부가 열린다. 학습자 “정확성을 지키는 규칙은 뭐가 있어?” 카리나 “도메인, 키, 엔티티 무결성을 구별해 보자.”
2. **원자값과 자료형(왼쪽 세로)**: 한 칸에 하나의 원자값, '정수형'과 '문자형' 명패. 카리나 “값은 원자값이어야 해. 자료형으로 정수형·문자형 등 유형도 제한하지.”
3. **디폴트와 CHECK(오른쪽 가로)**: '디폴트 값', 'CHECK 제약조건' 두 봉인. 학습자 “값의 범위도 제한할 수 있네!” 카리나 “디폴트 값과 CHECK 제약조건을 써.”
4. **키 중복 금지(중앙 역동 컷)**: 동일한 두 열쇠가 충돌해 하나가 거부됨. 카리나 “키 애트리뷰트에는 중복된 값이 존재하면 안 돼.” 학습자 “식별이 안 되니까!”
5. **기본 키 NULL 금지(하단 왼쪽)**: 학습자가 NULL 열쇠를 넣으려다 금지 문양을 본다. 카리나 “기본 키를 구성하는 어떤 애트리뷰트도 NULL일 수 없어.” 학습자 “복합 기본 키도 구성요소마다 금지구나!”
6. **예외와 정리(하단 오른쪽)**: '도메인: 원자값·유형·범위', '키: 중복 금지', '엔티티: 기본 키 NULL 금지'. 학습자 “대체 키에도 엔티티 무결성이 적용돼?” 카리나 “대체 키에는 적용되지 않아. 기본 키는 데이터 정의문에서 명시하지.”
