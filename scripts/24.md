# 24/24 — 수정할 때도 참조 무결성을 지켜야 해!

- **원본:** 「2장. 관계 데이터 모델과 제약조건 (1)(1).pdf」 49/49쪽, 2.4 「무결성 제약조건」의 **수정**
- **학습 목표:** (1) 수정하려는 애트리뷰트가 기본 키·외래 키인지 구별한다. (2) 키가 아닌 애트리뷰트 수정 시 자료형과 도메인 검사를 이해한다. (3) 키 수정은 삭제+삽입과 유사하여 제한·연쇄·NULL·DEFAULT 규칙이 적용됨을 이해한다.
- **예시 주의:** 원본 49쪽에 사원/부서 번호는 없다. 아래의 3→30, 3→99 등은 설명을 위한 가상 사례다.
- **캐릭터:** 카리나(백금발, 회색 눈, 초록/흰 줄무늬 목도리, 회색 조끼, 검은 망토), 학습자(긴 흑갈색 웨이브, 갈색 눈, 붉은 넥타이, 회색 조끼, 검은 망토). 여성 둘만 등장.
- **출력:** 세로 1024×1536 컬러 일본 만화 1장, 24/24 표기, 크기와 구도가 다른 서사적 6컷. 슬라이드식 6등분 금지.

## 컷별 완전 대본

### 1컷 — 데이터베이스 경보 (상단 와이드)
- **장면/행동:** 저녁의 데이터베이스 실습실. 학습자가 EMPLOYEE 데이터를 수정하려 하자 빨간 경보등이 울리고 카리나가 달려온다.
- **학습자:** “카리나! 데이터를 **수정**하려는데 왜 경보가 울려?”
- **카리나:** “DBMS는 먼저 **어느 애트리뷰트를 바꾸는지** 확인해.”
- **화면:** `UPDATE = 기존 투플의 값 수정`

### 2컷 — 두 개의 키가 빛나는 검사대 (사선 액션)
- **장면/행동:** 카리나가 손을 뻗자 기본 키(PK)와 외래 키(FK) 문양이 홀로그램으로 떠오른다. 학습자가 놀란다.
- **학습자:** “바꾸는 열이 **기본 키나 외래 키**인지부터 검사하는 거구나!”
- **카리나:** “맞아. 참조 무결성 검사에서 중요한 갈림길이지.”
- **필수 표기:** `기본 키(PK)`, `외래 키(FK)`

### 3컷 — 키가 아닌 이름 변경 (손과 모니터 클로즈업)
- **장면/행동:** 학습자가 EMPLOYEE의 ENAME을 지은에서 지민으로 고친다. 도메인 검사 램프가 녹색으로 변한다.
- **학습자:** “이름처럼 **키가 아닌 열**을 고치면?”
- **카리나:** “참조 무결성은 건드리지 않아. 새 값의 **자료형·도메인**을 확인하면 돼.”
- **화면:** `ENAME: '지은' → '지민'` (가상 예시)
- **주의:** 다른 모든 제약조건 검사가 불필요하다고 말하지 않는다.

### 4컷 — 잘못된 외래 키 변경 (긴박한 표정)
- **장면/행동:** 학습자가 EMPLOYEE.DNO를 3에서 99로 바꾸려 한다. DEPARTMENT.DEPTNO에 99가 없다는 빨간 경고. 카리나가 손을 들어 막는다.
- **학습자:** “외래 키 `DNO`를 없는 부서 `99`로 바꾸면?”
- **카리나:** “참조할 부서가 없으면 **참조 무결성 위반**이야!”
- **화면:** `EMPLOYEE.DNO → DEPARTMENT.DEPTNO`, `99 없음 → 거절` (가상 예시)

### 5컷 — 기본 키를 바꾸는 도미노 (가장 넓은 액션 컷)
- **장면/행동:** `DEPARTMENT.DEPTNO: 3 → 30` 도미노가 움직이자 `EMPLOYEE.DNO=3` 도미노들이 흔들린다. 카리나가 도미노를 붙잡고 선택지를 보여준다.
- **학습자:** “부서의 **기본 키**를 바꾸면 직원들 외래 키는?”
- **카리나:** “설정에 따라 **제한(RESTRICT)**은 거절하고, **연쇄(CASCADE)**는 참조 값도 함께 바꿔.”
- **보조문:** `SET NULL / SET DEFAULT도 조건에 따라 적용`
- **주의:** CASCADE는 ON UPDATE CASCADE가 설정된 경우만, 3→30은 가상 예시.

### 6컷 — 무결성 통과의 문 (하단 가로 결말)
- **장면/행동:** 두 여성이 ‘무결성 통과’라는 빛나는 문을 열고 앞으로 나아간다. 학습자가 고개를 끄덕이고 카리나가 살짝 미소 짓는다.
- **학습자:** “키 수정은 **기존 투플 삭제 + 새 투플 삽입**처럼 생각하면 되는 거네!”
- **카리나:** “정확해. 삽입·삭제 때 배운 **제한·연쇄·NULL·DEFAULT** 규칙을 수정에도 적용해.”
- **자막:** `키인지 검사 → 새 값 검증 → 참조 무결성 유지`

## 검수 기준
- 24/24 한 페이지만, 여성 두 인물 외 추가 등장 금지.
- 원본 49쪽의 핵심 세 가지(키 검사 / 비키의 자료형·도메인 / 키 수정의 삭제+삽입 및 참조 규칙)를 모두 설명.
- 외래 키 방향 `EMPLOYEE.DNO → DEPARTMENT.DEPTNO` 정확히.
- 이미지 생성은 최초 순회에서 1회만, 불일치 시 기록하고 이후 보충 단계로 이동.
